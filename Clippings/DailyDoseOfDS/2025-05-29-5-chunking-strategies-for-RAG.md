# RAG 的 5 种分块策略

RAG 的典型流程中，附加文档可能很大，因此第一步通常要把长文档切成更小、可管理的片段。这样做的关键目的，是让文本能够装入嵌入模型的输入长度限制。

## 1. 固定大小分块

按预先设定的字符数、词数或 token 数，把文本切成大小一致的片段。

直接切分可能打断语义流，因此建议让相邻片段保留一部分重叠内容。它实现简单；所有片段大小相同，也便于批处理。不过，它往往会在句子或观点中间切断文本，使重要信息分散到不同片段中。

## 2. 语义分块

- 先按句子、段落或主题区段等有意义的单元切分文档。
- 为每个单元生成嵌入向量。
- 从第一个单元开始，若它与下一单元的嵌入余弦相似度很高，就把两者归入同一片段。
- 持续这一过程；一旦相似度显著下降，就开始新的片段并重复。

与固定大小分块相比，这种方式保留了自然语言的流动性和完整观点。片段的语义更丰富，因而可提升检索准确性，并让 LLM 产生更连贯、相关的回答。其不足是：判断余弦相似度何时“显著下降”需要阈值，而这个阈值会随文档而变化。

## 3. 递归分块

先按照段落、章节等天然分隔符切分；若某个片段超过预设的大小上限，再把它继续切成更小的片段。未超过限制的片段则不再切分。

这种方法同样有助于保持自然语言流和完整观点。例如，先得到两个段落片段，再只继续拆分其中过大的第一段。代价是实现与计算复杂度会额外增加。

## 4. 基于文档结构的分块

利用标题、章节或段落等文档固有结构来定义边界，使分块与文档的逻辑章节对齐，从而保持结构完整性。

这种方法假定文档本身具有清晰结构，但并非所有文档都满足该条件。此外，片段长度可能不一致，甚至超过模型 token 限制；可结合递归切分来处理这一问题。

## 5. 基于 LLM 的分块

通过提示 LLM 生成语义独立且有意义的片段。由于 LLM 能理解上下文和含义，而不只是使用前四种方法中的简单启发式规则，因此这种方法具有较高的语义准确性。

相应地，它也是五种方法中计算开销最大的方案。还需要注意 LLM 通常有有限的上下文窗口。

## 选择建议

每种策略都有优势和取舍。原文指出，语义分块在许多场景中表现不错，但仍需要测试；最终选择取决于内容性质、嵌入模型能力和计算资源等因素。
