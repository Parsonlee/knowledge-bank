# RAG 与微调的可视化解释（RAG & Fine-tuning, explained visually.）

如果您正在构建现实世界中的 LLM 应用，您很少能够不对模型进行调整就直接开箱即用。

开发者通常将 RAG（检索增强生成）和微调（Fine-tuning）视为可以互换的选项，但实际上并非如此。

RAG 和微调解决的是根本不同的问题。前者控制模型在运行时**知道什么**，而后者改变模型默认的**行为方式**。

这里为您梳理它们的区别：

对于 **RAG**：
RAG 运行在推理阶段。当用户发送查询时，检索器会搜索您的知识库（如 PDF、向量数据库、API 或文档），提取相关上下文，并连同查询一起传递给 LLM。**模型的权重永远不会改变。** 您实际上是在运行时给 LLM 提供了一份“小抄”。

**微调**则截然不同：
它发生在离线阶段，即部署之前。您使用特定领域的数据来训练模型，**模型的权重确实会更新**。从此，模型默认的行为方式会发生改变。

微调的目的是改变模型的表现形式，比如它的语气、词汇偏好、回复结构，或是特定的推理模式。

有两个问题可以帮助您决定需要哪一种：

* 您的任务需要多少外部知识？
* 您需要多大程度的行为适应？

如果您需要模型引用特定的文档、产品目录，或者任何频繁更新的内容，这通常属于 **RAG** 的范畴。

如果您需要模型采用内部专业术语，匹配特定的写作风格，或者遵循特定领域的推理模式，这主要属于**微调**的范畴。

举个例子，LLM 可能会难以总结公司会议记录，因为发言者使用了模型从未见过的内部行话。微调可以解决这个问题。

话虽如此，在生产系统中，您往往需要同时使用两者。一个客户支持机器人可能需要从产品文档中提取答案（RAG），同时以您品牌的独特口吻进行回复（微调）。

简单的结论是：

* **RAG** → 模型应该知道什么？
* **微调** → 模型应该如何表现？

它们并不是竞争关系，而是 LLM 技术栈中互补的两个层级。
