# 多GPU训练的4种策略（4 strategies for Multi-GPU training.）

默认情况下，深度学习模型仅利用单个 GPU 进行训练，即使有多个 GPU 可用也是如此。

训练模型的一个理想方法是将训练工作负载分布到多个 GPU 上。

下面探讨多 GPU 训练的四种常见策略：

**#1) 模型并行 (Model parallelism)**
- 模型的不分部（或层）被放置在不同的 GPU 上。
- 适用于无法放入单个 GPU 的超大模型。
- 然而，模型并行也引入了严重的瓶颈，因为当激活从一个 GPU 转移到另一个 GPU 时，需要在 GPU 之间进行数据流动。

**#2) 张量并行 (Tensor parallelism)**
- 将单个张量操作分布并处理到多个设备或处理器上。
- 它基于这样的理念：一个大型张量操作（如矩阵乘法）可以划分为较小的张量操作，并且每个较小的操作都可以在单独的设备或处理器上执行。
- 这种并行化策略本质上已经内置在 PyTorch 和其他深度学习框架的标准实现中，但它们在分布式环境中变得更加显著。

**#3) 数据并行 (Data parallelism)**
- 在所有 GPU 上复制模型。
- 将可用数据划分为更小的批次 (batches)，每个批次由单独的 GPU 处理。
- 然后聚合来自每个 GPU 的更新（或梯度），并用它们来更新每个 GPU 上的模型参数。

**#4) 流水线并行 (Pipeline parallelism)**
- 这通常被认为是数据并行和模型并行的结合。
- 因此，标准模型并行的主要问题是：当数据正在通过第二个 GPU 中的层传播时，第一个 GPU 会处于空闲状态。
- 流水线并行通过在第一个 GPU 完成对第一个微批次 (micro-batch) 的计算并将激活转移到第二个 GPU 中的层后，立即加载下一个微批次的数据来解决这个问题。这个过程看起来像这样：
  - 第 1 个微批次穿过第 1 个 GPU 上的层。
  - 第 2 个 GPU 接收来自第 1 个 GPU 的关于第 1 个微批次的激活。
  - 当第 2 个 GPU 通过层传递数据时，另一个微批次被加载到第 1 个 GPU 上。
  - 该过程持续进行。
- 这样一来 GPU 利用率得到了极大的提高。
