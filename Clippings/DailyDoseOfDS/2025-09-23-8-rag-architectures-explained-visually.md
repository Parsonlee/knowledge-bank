# 8 种 RAG 架构的可视化解析（8 RAG architectures, explained visually.）

我们准备了以下视觉图表，详细解析了在 AI 系统中使用的 8 种 RAG（检索增强生成）架构：

让我们简要讨论一下它们：

**1) 基础 RAG (Naive RAG)**
* 纯粹基于查询向量和存储向量之间的余弦相似度来检索文档。
* 最适合于直接进行语义匹配即可解决的简单、基于事实的查询。

**2) 多模态 RAG (Multimodal RAG)**
* 通过跨模态进行向量化和检索来处理多种数据类型（文本、图像、音频等）。
* 理想适用于跨模态检索任务，比如利用文本和图像双重上下文来回答文字查询。

**3) HyDE 架构 (HyDE)**
* 当查询与目标文档在语义上不够相似时使用。
* 此技术会在检索之前，先根据查询生成一份“假设性答案”文档。
* 然后使用这份生成文档的向量表示来查找更相关、真实的底层文档。

**4) 纠错型 RAG (Corrective RAG)**
* 通过将检索结果与可信赖来源（例如网络搜索）进行对比，来验证检索到的信息。
* 确保信息是最新的且准确的，在将上下文传递给 LLM 之前对其进行过滤或纠错。

**5) 知识图谱 RAG (Graph RAG)**
* 将检索到的内容转换为知识图谱，以捕获实体及其之间的关联关系。
* 通过向 LLM 提供结构化的关系上下文以及原始文本，增强其推理能力。

**6) 混合 RAG (Hybrid RAG)**
* 在单一流水线中将稠密向量检索与基于图的检索相结合。
* 当任务同时需要非结构化文本和结构化关系数据才能提供更丰富的答案时非常有用。

**7) 自适应 RAG (Adaptive RAG)**
* 动态决定一个查询是只需要简单的直接检索，还是需要多步的推理链。
* 将复杂的查询分解成更小的子查询，以实现更好的覆盖率和精确度。

**8) 智能体式 RAG (Agentic RAG)**
* 采用具备规划、推理（如 ReAct、CoT）和记忆能力的 AI 智能体，协调多个来源的数据检索。
* 最适合需要使用工具、外部 API 或者组合多种 RAG 技术的复杂工作流场景。
