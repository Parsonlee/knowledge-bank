# 知识图谱降噪：实体与概念的筛选收敛指南

> **核心原则**：双链是昂贵的拓扑契约，普通文本是极高信噪比的保护色。宁缺勿滥，无损降级。

---

## 1. 痛点：双链通胀与“知识孤岛”

在搭建双链知识库（如 Obsidian）或引入 AI Agent 自动化构建 LLM-Wiki 时，最容易陷入的误区是**“双链通胀”**：
- **见名就链**：文章里提到托尔斯泰、乔布斯或某个作者，顺手打上 `[[实体_xxx]]`；
- **逢词就建**：文中出现一个新奇的形容词或临时观点，立刻建一个 `[[概念_xxx]]`；
- **过度连接**：把文学借喻、引言背景等辅助修辞当成了本体知识。

**后果**：全库充斥着大量入度只有 1（In-degree ≤ 1）的孤立节点。图谱看似繁密，实则信噪比极低，且在后续文章重构或删除时，极易诱发成片的悬挂死链。

---

## 2. 实体（Entity）准入法则

实体代表客观存在的具象主体（人物、机构、开源项目、产品等）。创建 `[[entities/实体_xxx]]` 必须同时跨过以下两道门槛：

| 维度 | 准入门槛 | 判定标准 |
| :--- | :--- | :--- |
| **深度门槛**（论述深度） | **≥ 3 句话本体论述** | 原文必须对该主体本身（架构、生平、机理、商业模式）有实质性剖析；仅作为背景、修辞、引言或一次性论据的，**坚决不建实体**。 |
| **广度门槛**（跨篇复用） | **具备跨文章复利价值** | 该实体是否是知识库长期关注的基石对象？预期未来是否会在其他文章中产生 2 次以上的真实交叉引用？ |

### 典型反例与纠偏示范
- ❌ **修辞借喻类人物/书名**：读随笔提到《伊凡·伊里奇之死》与托尔斯泰对人生的反省。  
  👉 **纠偏**：这是作者的论证修辞，而非在研究托尔斯泰文学。**不建实体**，正文保留纯文本。
- ❌ **一次性博文作者/学者**：读一篇博客提到 Jiabin Lu 或 James Carse。  
  👉 **纠偏**：若该学者/博主在全库没有持续系统性收录，**不建实体**，仅在元数据以纯文本标注作者。
- ❌ **一次性边缘工具/第三方小库**：某篇教程里临时引用的脚本工具。  
  👉 **纠偏**：非核心技术栈不建实体，避免污染图谱。

---

## 3. 概念（Concept）准入法则

概念代表抽象的认知模型、算法逻辑、方法论或架构范式。创建 `[[concepts/概念_xxx]]` 的筛选逻辑如下：

### 准入标准（三看）
1. **看核心性**：是否属于文章的核心论述对象或主要创新点（如《有限与无限的游戏》作为人生哲学模型，或 ColBERT 的延迟交互机制）。
2. **看抽象度**：是否具备可迁移、跨领域的通用解释力，而非单篇文章特有的“一次性自造词”。
3. **看独特性**：避开泛滥的常识大词（如不建“深度学习”、“Python编程”等大而无当的概念页）。

---

## 4. 关键心智跃迁：无损降级（Plain Text）

许多人在整理知识库时存在**“不打双链知识就会丢”的损失厌恶**。必须建立一个核心心智模型：

> **“在正文中提及”与“在图谱中建链”是两个完全解耦的层次。**

```
┌─────────────────────────────────────────────────────────────┐
│                    正文语义层（完整保留）                     │
│  "结合托尔斯泰中篇小说《伊凡·伊里奇之死》与乔布斯向死而生的论述..."     │
└──────────────────────────────┬──────────────────────────────┘
                               │ 评估门槛：仅为论据修辞，缺乏本体研究
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                    图谱网络层（无损降级）                     │
│  ❌ 避免创建：[[entities/实体_托尔斯泰]]                       │
│  ❌ 避免创建：[[entities/实体_伊凡·伊里奇之死]]                 │
│  ✅ 降级处理：正文保留纯文本（Plain Text），图谱零噪点        │
└─────────────────────────────────────────────────────────────┘
```

- **纯文本（Plain Text）**：负责精准表达行文语义，不增加图谱拓扑负担；
- **双链（Wikilinks `[[]]`）**：是昂贵的基础设施契约，只留给高价值的核心知识枢纽。

---

## 5. 治理与级联清理 SOP

当发现库内存在低价值实体/概念，或对已有文章进行精简时，应执行以下闭环清理流：

1. **出链微创剔除**：在 Source 摘要页中，将已废弃的实体链接改写为纯文本（如 `[[entities/实体_xxx|张三]]` → `张三`）。
2. **下游概念解链**：检查依赖该实体的概念页，移除死链与关联实体字段，避免留下断裂悬挂。
3. **物理文件归宿**：经确认无跨篇价值后物理删除对应 `.md` 文件，禁止留空文件或无源页面。
4. **总索引注销**：从 `wiki/index.md` 移除对应条目，保持索引 100% 映射。
5. **门禁校验**：运行 `vault_lint`（入度审计与死链扫描），确保全库 0 Errors 绿灯闭环。
