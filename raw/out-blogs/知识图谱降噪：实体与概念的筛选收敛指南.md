# 知识图谱降噪：实体与概念的筛选收敛指南

> **核心原则**：双链是昂贵的拓扑契约，普通文本是极高信噪比的保护色。宁缺勿滥，模型聚合，无损降级。

---

## 1. 痛点：双链通胀与“知识孤岛”

在搭建个人知识库（Obsidian）或引入 AI Agent 自动化构建 LLM-Wiki 时，最容易出现的图谱隐疾是**“双链通胀（Wikilink Inflation）”**：
- **见名就链**：文章里提到托尔斯泰、乔布斯、或某篇博客的原作者，顺手就建一个 `[[实体_xxx]]`；
- **逢词就建**：文中出现一个新奇的术语或临时词汇，立刻建一个 `[[概念_xxx]]`；
- **过度连接**：把文学借喻、随笔修辞等背景信息错当成核心本体。

**后果**：全库充斥着大量**入度仅为 1（In-degree ≤ 1）的孤立节点**。图谱表面看枝繁叶茂，实际有效信噪比极低；且一旦未来文章变动或删除，极易引发成片悬挂死链。

---

## 2. 实体治理实战：低频扫描与“五维分类筛选法”

在真实的治理实践中，我们通过脚本（`vault_lint.py`）对全库图谱进行了量化拓扑扫描：在先行清理了入度为 0 的绝对孤立实体后，系统仍扫描出 **40 个全库仅被引用 1 次的低频边缘实体**。

面对这批“合规但边缘”的实体，不能粗暴全删，也不能任其堆积。我们将其拆解为 **五维分类体系** 并执行差异化决策：

```
                    ┌── 1. 顶级基建与大厂 (OpenAI, Anthropic, NVIDIA) ───► [无条件保留] 全局锚点
                    ├── 2. 开源框架与基石工具 (uv, LangSmith, Docling) ──► [保留] 核心技术栈
全库低频实体扫描 ───┼── 3. 模型与算法细分 (GPT-5.6, GLM-5.2, Gemma3) ─────► [家族化聚合] 降维合并为系列
 (In-degree ≤ 1)    ├── 4. 垂直实验室与研究团队 (Thinking Machines Lab) ──► [极严门槛] 仅留战略跟踪者
                    └── 5. 单篇人物/博主/修辞借喻 (乔布斯, 评论尸, 托尔斯泰) ─► [坚决清理] 正文降级为纯文本
```

### 实体五维分类决策矩阵

| 类别 | 实体类型与代表案例 | 治理策略 | 判定逻辑与准入标准 |
| :--- | :--- | :--- | :--- |
| **一、顶级基建与大厂** | `OpenAI`, `Anthropic`, `NVIDIA`, `DeepMind`, `FastAPI` | 🟢 **全部保留** | **知识图谱的全局锚点**。即便当前库内仅入库了一两篇直接文献，它们也是整个行业技术体系的根节点，必须长期驻留。 |
| **二、开源主流工具与框架** | `uv`, `LangSmith`, `Unsloth`, `CherryStudio`, `Docling` 等 | 🟢 **全部保留** | **高频实操技术栈**。属于开发者日常高频调用的基础设施，具备高确定性的后续复用价值。 |
| **三、特定模型与算法版本** | `GLM-5.2`, `GPT-5.6`, `Gemma3`, `DiT`, `Florence-2` | 🔄 **模型家族化聚合** | **核心创新策略**。避免每个点版本孤立建页，统一聚合升维为 `[[实体_GLM系列]]`、`[[实体_GPT系列]]`、`[[实体_Gemma系列]]`，集中沉淀演进与评测经验。 |
| **四、研究机构与垂直实验室** | `Thinking_Machines_Lab`, `METR`, `陈丹琦团队`, `Surge_AI` | 🟡 **极高门槛保留** | 仅保留具备**持续技术路线突破与长线追踪价值**的标杆团队（如 Lilian Weng 创办的 Thinking Machines Lab）；单篇合作组或常规评测机构降级为文本。 |
| **五、单篇人物、博主与修辞借喻** | `史蒂夫·乔布斯`, `评论尸`, `翻斗花园二蛋`, `托尔斯泰`, `Jiabin Lu` | 🔴 **坚决清理与降级** | **低复利重灾区**。仅在单篇随笔/教程中出现，或纯属借喻论据。除个人专属实体（如 `[[实体_Hugo_Yang]]` 用于个人归档）外，全部降级为正文纯文本。 |

## 3. 概念（Concept）准入法则

概念代表抽象的认知模型、算法逻辑、方法论或架构范式。创建 `[[concepts/概念_xxx]]` 必须通过**“三看准则”**：

1. **看核心性**：是否属于文章的核心论述对象或第一性原理（如《有限与无限的游戏》作为人生哲学模型，或 ColBERT 的延迟交互机制）。
2. **看抽象度**：是否具备可跨领域迁移的通用解释力，坚决拒绝单篇文章特有的“一次性自造词”。
3. **看独特性**：避开常识大词（严禁建“深度学习”、“Python编程”等大而无当的概念页）。

## 4. 关键心智跃迁：无损降级（Plain Text）

许多人在整理笔记时有一种**“不打双链知识就会丢”的损失厌恶**。必须建立一个核心心智模型：

> **“在正文中提及”与“在图谱中建链”是两个完全解耦的层次。**

```
┌─────────────────────────────────────────────────────────────┐
│                    正文语义层（完整保留）                     │
│  "结合托尔斯泰中篇小说《伊凡·伊里奇之死》与乔布斯向死而生的论述..."     │
└──────────────────────────────┬──────────────────────────────┘
                               │ 评估：仅为人生反思论据，缺乏本体研究
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                    图谱网络层（无损降级）                     │
│  ❌ 避免创建：[[entities/实体_托尔斯泰]]                       │
│  ❌ 避免创建：[[entities/实体_伊凡·伊里奇之死]]                 │
│  ✅ 降级处理：正文保留纯文本（Plain Text），图谱保持零噪点     │
└─────────────────────────────────────────────────────────────┘
```

- **纯文本（Plain Text）**：忠实承载叙事与事实细节，零拓扑负担；
- **双链（Wikilinks `[[]]`）**：是昂贵的基础设施契约，只授予真正承担图谱枢纽作用的高价值节点。

## 5. 落地实操：人机协同审核与闭环清理 SOP

通过自动化脚本与人类审阅协同，形成低频实体的“扫描-审阅-微创剔除-闭环”SOP：

1. **自动拓扑诊断**：运行 `vault_lint.py` 提取入度 $\le 1$ 实体列表，按五维体系自动归类并生成审阅清单。
2. **人机决策裁决**：
   - 基础设施/核心大厂：一键确认保留；
   - 细分模型版本：指示 Agent 归并至家族系列实体；
   - 边缘博主/修辞人物：下达清理与文本降级指令。
3. **行内微创剔除**：在 Source 摘要页中将废弃实体精准降为纯文本（如 `[[entities/实体_xxx|张三]]` → `张三`），严禁粗暴整行删除导致相邻有效链接连带丢失。
4. **下游依赖解耦**：检查引用该实体的概念页，移除死链与字段挂载。
5. **物理删除与索引注销**：物理删除废弃实体文件，同步从 `wiki/index.md` 剔除登记条目。
6. **自动化门禁闭环**：重新跑通 `vault_lint`，确保全库 **0 死链、Schema 100% 合规、0 报错**。
