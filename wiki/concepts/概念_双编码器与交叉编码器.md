# 双编码器与交叉编码器 (Bi-encoders vs Cross-encoders)

## 基础定位
在现实世界的自然语言处理（NLP）应用中，**成对句子评分（Pairwise Sentence Scoring）**是一个至关重要的基石。它隐式或显式地支撑着诸多核心系统：
- **RAG 检索**：从海量文档中召回与 Query 最相关的上下文，是 RAG 系统（“80% 检索，20% 生成”）中决定上限的一环。
- **问答系统**：匹配用户提问与候选答案的语义契合度。
- **信息检索 (IR)**：根据关联得分对候选文档进行精准排序。
- **重复项检测**：判断社区平台（如 Quora、StackOverflow 等）中两个文本是否属于语义重复。

## 核心架构对比

为了解决句子对的相似度计算问题，目前业界形成了两种主流的 State-of-the-Art (SOTA) 编码器架构：

| 特性 | 双编码器 (Bi-encoders) | 交叉编码器 (Cross-encoders) |
| :--- | :--- | :--- |
| **工作原理** | 分别、独立地对输入的两句话进行编码，生成对应的向量表示，然后通过简单的向量内积、余弦相似度等度量方式计算得分。 | 将两句话拼接（通常用 `[SEP]` 隔开）后一同送入同一个模型中，在整个编码过程中，利用注意力机制进行两句话字词层级的全方位交叉交互。 |
| **计算开销** | 极低（向量可以提前离线计算并存入向量数据库，在线检索只需进行向量计算）。 | 极高（每一次打分都必须将拼接后的长文本送入模型中，无法提前离线计算）。 |
| **检索效率** | 极高，适合数百万甚至数亿级别文本的**大规模召回阶段**。 | 极低，不适合大规模初筛，常用于数十至数百量级的**精排/重排 (Rerank) 阶段**。 |
| **精度表现** | 相对较低（由于两句话在编码阶段缺乏相互的信息流动，存在“漏网之鱼”）。 | 极高（能够捕捉到两句话之间非常微妙的语义对齐和交互）。 |

## AugSBERT 架构
为了兼顾双编码器的高计算效率与交叉编码器的高精度，研究人员提出了 **AugSBERT** 架构。
AugSBERT 通过将双编码器与交叉编码器结合：
- 首先使用交叉编码器对海量无标注数据（或难以获取的大量样本对）进行高质量的伪标注（Soft Labeling）。
- 接着将这些被“扩增”并带有伪标签的句子对数据用来训练双编码器。
- 这样训练出的双编码器能在保持极速向量检索特性的同时，显著逼近交叉编码器的精度上限，有效解决了目标领域数据稀缺的难题。

## 延迟交互机制：ColBERT
为了解决双编码器精度低和交叉编码器算力开销巨大的问题，**ColBERT** 提出了一种**延迟交互（Late Interaction）**机制，巧妙地融合了两者的核心优势：
- **离线编码与吞吐量保障**：与双编码器相似，ColBERT 允许将所有的 Document 词级（token-level）嵌入向量进行离线预计算和索引。这保证了在检索阶段，系统无需针对每个 Query-Document 组合进行庞大的 BERT 前向传播，依然拥有接近双编码器级别的极高检索吞吐量。
- **保留词字层级的延迟交互（Late Interaction）**：与双编码器在编码后只保留单一的 `[CLS]` 汇总向量不同，ColBERT 保留了 Query 和 Document 所有 token 级别特征向量的交互矩阵。
- **MaxSim 算子进行语义对齐**：在检索时，ColBERT 分别对 Query 和 Document 进行编码，然后对于 Query 中的每一个 token，在 Document 的所有 token 中寻找余弦相似度（或点积）最大的那个 token（即 MaxSim 操作），最后将 Query 所有 token 的最大相似度累加，作为最终的相关性得分。通过这种词对词的延迟交互计算，ColBERT 能够捕获极佳的语义精细度，取得逼近交叉编码器的精准检索效果。
