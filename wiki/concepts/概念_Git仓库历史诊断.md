# 概念：Git 仓库历史诊断

## 定义

Git 仓库历史诊断是在深入阅读源码前，先从提交历史中提取结构与团队信号，判断哪些文件、时期和维护关系值得优先调查。它提供的是侦察线索，不是对代码质量或团队健康的自动结论。

## 五类信号

1. **变更热点**：统计文件被提交触达的频率，定位活跃或反复修改的区域。
2. **维护者活跃度**：比较全历史与近期贡献者，观察关键维护者是否仍在以及公交因子。
3. **缺陷聚集**：按修复类提交关键词聚合文件，并与变更热点交叉，寻找“改得多且经常修”的区域。
4. **提交趋势**：按月查看提交数量的长期形状，结合人员、发布和自动化事件解释波动。
5. **救火信号**：检索回滚、热修和紧急提交，评估发布流程是否频繁进入事故响应状态。

## 解读边界

- 自动生成文件、索引文件和锁文件会制造结构性高频变更，应先排除或单独解释。
- Squash Merge、机器人提交、作者名称不一致会扭曲贡献者统计。
- 缺陷和救火关键词依赖团队提交规范，既会漏报，也会因文件名或普通文本误报。
- 提交量变化只能提示进一步调查方向，不能单独证明项目在加速、衰退或质量恶化。

## 使用方式

先在业务代码目录运行命令，再把变更热点与缺陷聚集结果交叉；随后查看这些文件的提交记录、责任人和相关事件，形成代码阅读顺序，而不是直接把统计结果当作结论。
